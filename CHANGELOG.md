# Changelog (изменения после этапа 21 плана веба)

## 2026-10-03
- Этап 21: тестовая среда. `server/app.js` отделён от запуска (`server/server.js`); `db/migrator.js` выделен из `db/migrate.js`.
- Исправлен исполнитель миграций: секция `-- DOWN` больше не выполняется при применении (раньше `001_init.sql` сразу удалял свои таблицы).
- Исправлена миграция `009`: убраны невалидные `ADD CONSTRAINT ... UNIQUE USING INDEX` (на чистую базу не применялась).
- Добавлены локальная тестовая БД (`scripts/test-db.sh`), интеграционные тесты, защита от запуска тестов на нелокальной БД, запуск тестов в GitHub Actions перед выкладкой.

## 2026-10-03 (этап 22: безопасность и общий backend)
- Вход: сервер сам проверяет токен у Яндекса и создаёт `uid` (`u_<uuid>`); `uid` и профиль из тела запроса игнорируются. Старые `/auth/login`, `/auth/refresh`, `/auth/logout` удалены.
- Аккаунты в базе (`users`, `identities`), профили больше не в памяти; `POST /profile/me` исправлен.
- Секреты обязательны, запасные значения запрещены. Единый выпуск токенов в `utils/jwt.js`; refresh-токены уникальны (`jti`).
- Refresh: ротация одной транзакцией, повторное использование отозванного токена отзывает все сессии.
- Ограничение частоты запросов на ручки входа (по IP).
- Изоляция: id комнаты, группы или прибора из другого проекта отклоняется `409 ID_CONFLICT` (комнаты раньше перезаписывались); `group_id` и `room_id` должны принадлежать проекту.
- Пакет (`batch`) стал настоящей транзакцией (раньше записи шли отдельными соединениями и не откатывались); не более 500 операций (`413`); несуществующий проект даёт `404`.
- Правило конфликтов: «последний победил по записи» по `clientUpdatedAt`; устаревший `baseVersion` больше не влияет.
- Профиль возвращает `planSource`, `capabilities` и `projectsLimit`; `/billing/status` показывает ручную выдачу.
- Ручная выдача PRO (`entitlements`) и консольные команды `npm run admin:*`.

## 2026-10-03 (этап 23: документы проекта)
- Документы проекта (`setup`, `cable_defaults`, `phase_overrides`, `apparatus_selections`, `estimate_items`, `panel_layout`): список, чтение, запись с проверкой версии (`409 version_conflict`), защита от записи старой схемы (`409 schema_downgrade`), мягкое удаление; миграция `030`.
- Доступ по праву PRO на сервере (`402 pro_required`), данные после окончания PRO сохраняются (`locked` в списке).
- История последних 20 версий; команды `npm run admin:doc-versions` и `admin:doc-restore` (восстановление новой версией, с журналом).
- Запись документа поднимает версию и время проекта.
- Единые JSON-ответы для слишком большого тела (`413`), битого JSON (`400`), запрещённого CORS (`403`) и неизвестных адресов (`404`).
- Тесты: исправлена нестабильность (случайные 404, `socket hang up`, зависания): supertest слушал порт на `::`, а клиент подключался к `127.0.0.1`, и запрос иногда попадал в чужую программу на том же порту. Теперь тестовый сервер явно привязан к `127.0.0.1` (`tests/helpers.js`).

## 2026-10-03 (этап 24: аккаунт на сайте)
- `POST /v1/profile/delete { "confirm": true }`: удаление аккаунта и данных пользователя одной транзакцией (проекты со всем содержимым, документы и история, сессии, ручные выдачи PRO, профиль, способы входа). Сведения о подписке (`subscriptions`) и журнал (`audit_log`) сохраняются. Миграция `031` (`deleted_accounts`).
- Токен удалённого аккаунта перестаёт работать сразу (`401 account_deleted`), а не через 30 минут.
- CORS: разрешён заголовок `X-VoltHome-Client` (его отправляют сайт и приложение); запрещённый источник даёт `403 cors_forbidden` в формате JSON.
